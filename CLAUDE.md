# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A content repo, not a code project — a library of interview-ready system design docs. There is no build, test, or lint step; don't look for one.

## Layout

- `system-designs/*.md` — the actual content. Generated with the `system-design-generator` skill (`/system-design-generator`); use it to add a new company/product doc rather than writing one from scratch, so the header, research-sourcing tags, and section structure stay consistent.
- `reference_system_designs/*.pdf` — manual reading material for the user only. Not input to the skill; don't parse or summarize these unless explicitly asked.

## `system-designs/*.md` conventions

- Filename: kebab-case product/company name, e.g. `wispr-flow.md`.
- Every file opens with an HTML comment header (`Generated by`, `Target`, `Type`, `Generated` date, `Research sources`, `Artifact` link), then a title, one-line italic tagline, a **By the numbers** stat line, and a **Topics covered** list.
- Body uses numbered `## 01.` … `## NN.` sections (Requirements & Scope → Capacity Estimation → High-Level Architecture → APIs & Contracts → Data Model & Storage → product-specific deep dives), followed by unnumbered closing sections: Scaling & Caching, Failures & Reliability, Recap & Interview Cheat Sheet.
- Unconfirmed claims are tagged inline with `*(inferred — not publicly confirmed)*`; sourced claims with `*(sourced: ...)*`. Preserve this when hand-editing.
